### 2.3 最高优先级需求

> "要方便我后期改动"

这是制作者明确提出的第一优先级。具体落实为：

1. **内容与代码分离**：所有文字、项目、链接集中到一个 `src/data/profile.js`（或 `.json`）。
   改内容只需要编辑这一个文件，不需要理解 React。
2. **样式改起来要简单**：用 Tailwind 工具类，样式写在标签上，
   不出现"找这个字号定义在哪个 CSS 文件第几行"的情况。
3. **加新项目要简单**：往数据文件的项目数组里加一个对象即可，卡片自动生成。
4. **结构要直白**：组件按区块拆分（Hero / Projects / About / Contact），
   文件名一看就懂，每个文件不超过 150 行。

### 2.4 硬件约束（硬性要求）

> "如果需要的话，不要装到 C 盘，装 D 盘，我 C 盘快炸了"

- **C 盘剩余空间只有 13.4 GB**，必须保持不减少。
- **项目根目录固定在 `D:\www\portfolio`**，不要挪到桌面。
- 安装依赖产生的 `node_modules`（约 200–300 MB）留在项目内（= D 盘）。
- 构建时的临时文件必须重定向到 D 盘，见 `TECH_PLAN.md` 第 3 节。

## 4. 首版验收标准

做到以下程度就算首版完成：

1. `npm run dev` 能在本地起服务，浏览器打开能看到完整页面
2. 页面包含：顶部介绍区、项目展示区（含 SAChat 卡片）、关于区、联系方式区
3. 手机浏览器打开不变形（响应式）
4. 修改 `src/data/profile.js` 里的文字，页面对应位置立刻变化
5. 往项目数组里加一个对象，页面自动多出一张卡片
6. 构建产物 `npm run build` 能正常生成，且**全程 C 盘空间没有减少**
